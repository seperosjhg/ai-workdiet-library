2. 규칙 소재 실측 (md 파일 전수 점검)

기록되어 있던 원문 (memory 12–14행)
bat를 UTF-8로 저장하면 한국어 Windows cmd가 cp949로 읽어 한글이 깨지고 명령 오류 발생. 「chcp 65001」로는 해결 안 됨.
해결 우선순위: ① bat 내부 글자는 영어(ASCII)만 → ② 한글 필요시 bat를 ANSI(cp949)로 저장 → ③ 차선 UTF-8+BOM+chcp 65001.
→ 이번에 만든 bat은 정확히 ③번(가장 나쁜 선택)이었고, 심지어 BOM도 없었습니다.

3. 근본원인 — 2계층 하네스의 사각지대

[항상 로드]  CLAUDE.md  ────────── bat 규칙 없음 (PowerShell 규칙만)
             MEMORY.md 색인 ────── "bat 한글 인코딩" 주제어만, 행동지시 없음
                  │
                  │  ← 여기서 "찾아봐야 한다"는 신호가 발생하지 않음
                  ▼
[온디맨드]   automation-dev-rules.md ── 완전한 규칙 (recall 필요)
             01-PM실행SOP.md ────────── 완전한 규칙 (Read 필요)
컨텍스트 슬림화(2026-07-01) 과정에서 상세 규칙이 온디맨드 계층으로 이전되었으나, "bat을 만들 때 이 파일을 열어야 한다"는 트리거가 항상 로드 계층에 남지 않았습니다. 주제어만으로는 작업 중 자동 발화되지 않습니다. 이번 세션에서 bat 생성은 부수 작업(비밀번호 입력 도우미)이었고, 참고자료를 열지 않은 채 진행되어 규칙이 작동하지 않았습니다.

4. 조치 (완료)

5. 재발방지 원칙 (귀납)

"반복 실패 규칙은 온디맨드 계층에 두지 않는다."
  • 컨텍스트 슬림화로 상세를 참고자료로 옮길 때, 항상 로드 계층에는 요약이 아니라 "행동지시 1줄"을 남긴다. 주제어("~인코딩")는 트리거로 작동하지 않고, 명령문("ASCII 전용으로 만들 것")만 작동한다.
  • 산출물이 사용자 PC에서 직접 실행되는 파일(bat/exe/스크립트)이면, 생성 직후 실측 검증을 산출물의 일부로 취급한다(바이트 검사 + 실제 실행). 이번 건은 실행 검증을 사용자가 대신하게 되어 왕복 1턴이 소모됐다.
본 점검은 md 파일 6종 전수 grep + 실측 실행 검증 기반으로 작성됨. 추정 없음.
